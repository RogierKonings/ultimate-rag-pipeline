# Epic 8.2: Rust Retrieval Service

> **Priority:** **Critical** (Hot Path)
> **Estimated Effort:** 8-12 weeks
> **Dependencies:** Epic 8.1 (Rust Foundation)
> **Parent Epic:** [08-rust-rewrite-overview.md](08-rust-rewrite-overview.md)
> **Last Updated:** 2025-01-26

## Overview

Rewrite the retrieval service in Rust. This service handles hybrid search (semantic + keyword), query preprocessing, result fusion (RRF), reranking, ACL enforcement, and **video retrieval**. This is the **highest priority** candidate for Rust migration due to:

1. It's on the critical query path (user-facing latency)
2. RRF fusion is pure compute (10x+ speedup potential)
3. Clear service boundaries make migration low-risk
4. Mature Rust ecosystem for all dependencies

**Update (January 2025):** The retrieval service now includes video search capabilities with the `video_chunks` Qdrant collection. The service has grown to ~26,000 LOC with enhanced observability, resilience patterns, and tier configuration.

## Goals

- Implement high-performance hybrid search
- Port Reciprocal Rank Fusion (RRF) algorithm (**Quick Win: <1ms target**)
- Integrate cross-encoder reranking client
- Implement ACL filtering
- **Port video retrieval with clip generation** - NEW
- Create Axum-based REST API
- Achieve **p95 < 150ms** total latency (vs 250ms Python baseline)

## User Stories

### US-8.2.1: Query Preprocessing
**As a** developer
**I want** query preprocessing in Rust
**So that** queries are optimized before search

**Acceptance Criteria:**
- [ ] Query normalization (lowercase, trim)
- [ ] Query expansion (synonyms, optional)
- [ ] Query embedding generation (HTTP call to embedding service)
- [ ] Query caching with Redis
- [ ] Instruction prefix for BGE models

**Python Reference:** `services/retrieval/query/preprocessor.py`

### US-8.2.2: Semantic Search
**As a** developer
**I want** Qdrant semantic search in Rust
**So that** vector similarity search is performant

**Acceptance Criteria:**
- [ ] Vector search with top-k parameter
- [ ] Filter by tenant_id
- [ ] Filter by metadata fields
- [ ] Score threshold filtering
- [ ] Batch query support
- [ ] Connection pooling

**Python Reference:** `services/retrieval/search/semantic.py`

### US-8.2.3: Keyword Search
**As a** developer
**I want** OpenSearch keyword search in Rust
**So that** BM25 ranking is available

**Acceptance Criteria:**
- [ ] BM25 search with configurable fields
- [ ] Filter by tenant_id
- [ ] Highlight support
- [ ] Multi-match query builder
- [ ] Pagination support

**Python Reference:** `services/retrieval/search/keyword.py`

### US-8.2.4: Reciprocal Rank Fusion
**As a** developer
**I want** RRF implementation in Rust
**So that** semantic and keyword results are merged

**Acceptance Criteria:**
- [ ] RRF algorithm with configurable k constant (default 60)
- [ ] Configurable weights for semantic/keyword
- [ ] Deduplication by chunk_id
- [ ] Score normalization
- [ ] Preserve source metadata

**Python Reference:** `services/retrieval/search/fusion.py`

**Algorithm:**
```rust
fn rrf_score(rank: usize, k: f32) -> f32 {
    1.0 / (k + rank as f32)
}
```
