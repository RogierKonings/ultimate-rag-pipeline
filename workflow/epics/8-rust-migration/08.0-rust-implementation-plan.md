# Rust Rewrite: Prioritized Implementation Plan

> **Document Type:** Implementation Roadmap
> **Last Updated:** 2025-01-26
> **Strategy:** Performance-Critical Paths First, Risk-Minimized Incremental Delivery

## Executive Summary

This plan prioritizes work items by **performance impact**, starting with components that:

1. Are CPU-bound and benefit most from Rust (embedding, chunking, RRF, video processing)
2. Have mature Rust ecosystem equivalents
3. Can be integrated incrementally via PyO3 or service replacement
4. Allow early validation with measurable performance gains

**Update (January 2025):** The codebase has grown ~51% with a new video processing pipeline. This plan now includes video processing as a high-priority target due to its CPU-intensive nature.

## Priority Classification (Performance-Focused)

| Priority | Criteria | Risk | Timeline | Perf Impact |
|----------|----------|------|----------|-------------|
| **P0** | CPU-bound algorithms, pure compute | Very Low | Weeks 1-4 | **Very High** |
| **P1** | Foundation crates, ecosystem mature | Low | Weeks 5-12 | Medium |
| **P2** | Retrieval service (hot path) | Low-Medium | Weeks 13-24 | **High** |
| **P3** | Video processing pipeline | Medium | Weeks 25-36 | **High** |
| **P4** | Ingestion service | Medium-High | Weeks 37-48 | Medium |
| **P5** | Orchestrator (optional) | High | Weeks 49-64 | Low |

## Escape Hatches

If any phase proves too risky, these fallbacks are available:

1. **PDF/DOCX Parsing:** Keep as Python microservice, call via HTTP
2. **Semantic Chunking:** Use recursive chunker exclusively
3. **PII Detection:** HTTP call to Python Presidio service
4. **Video Transcription:** Keep Whisper in Python, call via HTTP
5. **Scene Detection:** Keep PySceneDetect in Python, call via HTTP
6. **Vision Analysis:** Always via HTTP to OpenAI/Ollama (no change needed)
7. **Orchestrator:** Keep Python orchestrator, only port retrieval/ingestion/video
8. **Full Abort:** Use PyO3 for hot paths only, keep Python services
