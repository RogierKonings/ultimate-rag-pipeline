# Epic 8.3: Rust Ingestion Service

> **Priority:** High
> **Estimated Effort:** 16-22 weeks (includes video processing)
> **Dependencies:** Epic 8.1 (Rust Foundation)
> **Parent Epic:** [08-rust-rewrite-overview.md](08-rust-rewrite-overview.md)
> **Last Updated:** 2025-01-26

## Overview

Rewrite the ingestion service in Rust. This is the most complex service due to document parsing, chunking algorithms, video processing pipeline, and the variety of source connectors. The biggest challenges are replacing Python's mature document parsing ecosystem (PyMuPDF, unstructured) and the new video processing pipeline (PySceneDetect, Whisper).

**Update (January 2025):** The ingestion service has grown significantly with the addition of a video processing pipeline. This epic now includes video processing as a high-priority component due to its CPU-intensive nature.

## Goals

- Implement document source connectors
- Port document parsers (PDF, DOCX, HTML, Markdown)
- Implement chunking strategies (recursive, semantic, hierarchical)
- **Port video processing pipeline (keyframes, OCR, scene detection, fusion)** - NEW
- Create embedding client with batching and caching
- Implement multi-store index writers
- Replace Celery with Rust-native async workers

## Complexity Assessment

This is the **highest effort** service to port due to:

1. **Document Parsing**: Python's `unstructured` and `PyMuPDF` are feature-rich. Rust alternatives exist but are less mature.
2. **Video Processing** (NEW): Keyframe extraction, scene detection, OCR, and content fusion are CPU-intensive and benefit from Rust performance.
3. **NLP for Semantic Chunking**: Spacy's sentence segmentation needs replacement (rust-bert, tokenizers).
4. **Celery Replacement**: Need to design async worker pool or use message queue directly.
5. **Many Connectors**: Each data source connector needs porting.

## User Stories

### US-8.3.1: Source Connector Interface
**As a** developer
**I want** a trait-based connector system
**So that** new sources can be added easily

**Acceptance Criteria:**
- [ ] `SourceConnector` trait definition
- [ ] `DocumentMetadata` struct
- [ ] Async streaming of documents
- [ ] Error handling per document
- [ ] Progress reporting

**Python Reference:** `services/ingestion/connectors/base.py`

```rust
#[async_trait]
pub trait SourceConnector: Send + Sync {
    async fn list_documents(&self) -> Result<Vec<DocumentMetadata>>;
    async fn fetch_document(&self, id: &str) -> Result<RawDocument>;
    async fn health_check(&self) -> Result<()>;
}
```

## Risk Mitigation

### PDF Parsing Risk
**Fallback Strategy:** Keep Python PDF parser as microservice, call via HTTP

### NLP/Semantic Chunking Risk
**Fallback Strategy:** Use simpler regex-based sentence splitting initially

### Celery Replacement Risk
**Fallback Strategy:** Use established message queue (NATS, RabbitMQ) with proven Rust clients
