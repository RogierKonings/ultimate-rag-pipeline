# Rust Rewrite: Prioritized Implementation Plan

> **Document Type:** Implementation Roadmap
> **Last Updated:** 2025-01-12
> **Strategy:** Low-Hanging Fruit First, Risk-Minimized Incremental Delivery

## Executive Summary

This plan prioritizes work items by **effort-to-value ratio**, starting with components that:
1. Have mature Rust ecosystem equivalents
2. Provide immediate performance benefits
3. Can be integrated incrementally (no big-bang required)
4. Allow early validation of the Rust approach

## Priority Classification

| Priority | Criteria | Risk | Timeline |
|----------|----------|------|----------|
| **P0** | Low effort, high value, mature Rust ecosystem | Low | Weeks 1-4 |
| **P1** | Medium effort, clear path, good ecosystem | Low-Medium | Weeks 5-12 |
| **P2** | Medium effort, some unknowns | Medium | Weeks 13-24 |
| **P3** | High effort, ecosystem gaps | High | Weeks 25-40 |
| **P4** | Very high effort, significant risk | Very High | Weeks 41-56 |

## Risk Mitigation Checkpoints

### Checkpoint 1: Week 4
- [ ] Can we build and test Rust code in CI?
- [ ] Do the basic crates compile and work?
- **Go/No-Go Decision:** Continue to Phase 1

### Checkpoint 2: Week 12
- [ ] Do all foundation crates pass integration tests?
- [ ] Are there any ecosystem blockers?
- **Go/No-Go Decision:** Continue to Retrieval Service

### Checkpoint 3: Week 24
- [ ] Is Rust retrieval service in shadow mode?
- [ ] Does performance meet expectations?
- [ ] Are there behavior regressions?
- **Go/No-Go Decision:** Continue to Ingestion or optimize

### Checkpoint 4: Week 44
- [ ] Is Rust ingestion functional?
- [ ] Have PDF/DOCX challenges been resolved?
- [ ] Is worker system reliable?
- **Go/No-Go Decision:** Continue to Orchestrator

### Checkpoint 5: Week 56
- [ ] Is state machine design validated?
- [ ] Does full pipeline work end-to-end?
- **Go/No-Go Decision:** Production cutover

## Escape Hatches

If any phase proves too risky, these fallbacks are available:

1. **PDF/DOCX Parsing:** Keep as Python microservice, call via HTTP
2. **Semantic Chunking:** Use recursive chunker exclusively
3. **PII Detection:** HTTP call to Python Presidio service
4. **Orchestrator:** Keep Python orchestrator, only port retrieval/ingestion
5. **Full Abort:** Use PyO3 for hot paths only, keep Python services
